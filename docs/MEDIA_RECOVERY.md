# Восстановление медиа

## Пакет со смешанными видео

Beta 5 (Fix) показывает «Совместимость медиафайлов», если части выбранных вложений нужны решения. Для файлов, пригодных к преобразованию, кнопка «Подготовить все совместимые копии и продолжить» применяет совместимый режим сразу. Для других файлов можно сохранить роль документа, исключить вложение или отменить подготовку. При необходимости установить FFmpeg и FFprobe выберите Windows-сборку на официальной странице FFmpeg и укажите пути к двум программам в настройках gTR. [Загрузки FFmpeg](https://ffmpeg.org/download.html)

Для MOV с подходящими дорожками H.264 и AAC gTR сначала проверяет перенос сжатых дорожек в MP4 без перекодирования. Копия получает faststart. Проверяются длительность, пропорции, поворот и сохранность дорожек. При необходимости gTR переходит к перекодированию в H.264/AAC.

Создание копий сохраняет оригинальные байты и выполняется локально. Проверенная копия может использоваться в последующей подготовке, включая подготовку после перезапуска. Настройки позволяют оценить объём кеша и удалить ненужные копии. Подготовленный пакет хранит собственные файлы.

## Что проверяет движок

В Beta 4 видеоатрибут требовал, чтобы экспорт уже содержал длительность, ширину и высоту. Отсутствие одного из полей позволяло подготовить обычный документ. Проверка ответа Telegram различала классы фотографии и документа. Видео тоже использует контейнер Telegram Document, поэтому этого признака было недостаточно. Для установления причины по конкретному прошлому файлу нужны его оригинал, параметры пакета и доступный ответ Telegram или снимок истории.

Beta 5 учитывает исходную роль файла и содержимое. MP4 может содержать несовместимый видеокодек. Файл, отправленный документом в исходном диалоге, сохраняет эту роль. Для подготовленного видео исходный контейнер, кодеки, длительность, размеры, частота кадров, поворот, проверка декодирования начала и положение блока moov записываются в манифесте. Проверяется тип, возвращённый методом загрузки. При расхождении подготовка серверной операции останавливается до запроса запуска.

В «Настройках» можно указать локальные FFmpeg и FFprobe. По умолчанию gTR ищет их в PATH и рядом друг с другом. FFprobe читает параметры потоков. FFmpeg проверяет небольшой фрагмент, создаёт миниатюры и, с согласия пользователя, совместимую копию. gTR ограничивает число процессов, время, доступные протоколы и память дочернего процесса Windows. Только FFmpeg, установленный пользователем, используется на этом компьютере.

| Режим видео | Действие |
|---|---|
| Оригинал | Подтверждённый MP4/H.264 с совместимыми дорожками сохраняется побайтно. Для остального требуется решение. |
| Совместимость | При необходимости создаётся отдельный MP4/H.264 с AAC и faststart. gTR проверяет итоговый тип, длительность и SHA-256. |
| Документ | Сохраняются оригинальные байты, тип выбирает пользователь. |
| Пропуск | Несовместимое видео остаётся в локальном проекте. Доступная подпись сохраняется в пакете. |

Вращение оригинала фиксируется в отчёте. Круглое видео требует подтверждённых квадратных размеров. В записи с несколькими вложениями и видео можно выбрать архив-документ либо исключить видео. Группировка истории Telegram остаётся локальной.

Голосовая дорожка передаётся с флагом голосового сообщения при подтверждённом Opus в подходящем контейнере и известной длительности. Поддерживаемые аудиофайлы могут передать название и исполнителя из тегов. Поддержка GIF, анимаций и стикеров опирается на сигнатуру файла и доступные метаданные. Расхождение или нехватка метаданных отображаются в плане. Для пропущенного файла остаётся предупреждение и доступная подпись.

Оригинальное имя, безопасное имя, имя сопоставления в History Import и имя из ответа Telegram хранятся отдельно. Контрольная сумма подтверждает байты локального пакета. Клиент Telegram может преобразовать фотографию. Точная проверка полученных байтов требует независимого чтения с согласия владельца.
