# gTR Beta 6 (Fix 2)

## Причина LOCAL_INVALID

Обе указанные операции ссылались на один и тот же манифест. Журнал фиксирует 318 записей источника, 312 сообщений к переносу и 218 вложений. Обе попытки дошли до `local_check` и завершились до отправки текста истории и начала загрузки вложений.

Пакет целиком проходит загрузчик Beta 6 (Fix), включая проверку атрибутов стикеров, точных имён маркеров, контрольных сумм пяти совместимых копий и файлов из экспорта. В прежней версии перед сетевой проверкой создавалась временная защищённая копия, а затем на том же диске создавалась ещё одна копия для журнала.

Для пакета одна копия занимает 703 880 306 байт. При воспроизведении с тем же пакетом и лимитом, равным измеренному запасу диска 900 767 744 байта, после первой копии остаётся 196 887 438 байт. Вызов `retain → copy_package → _require_space` останавливается, поскольку для второй копии требуется ещё 703 880 306 байт. Старый журнал записывал только `LOCAL_INVALID`. Объём свободного места установлен повторной локальной проверкой.

## Изменение проверки

Перед открытием готовой папки gTR использует один валидатор для форматов пакета, манифеста, файлов, атрибутов, истории и привязок. Подготовка публикует готовую папку после прохождения этого валидатора. Для проверки владельца используется защищённая копия из хранилища. Перед отправкой повторно сверяются её манифест и байты. Копия сохраняется для восстановления и диагностики.

Сбой до отправки сохраняется в журнале как локальная ошибка. Пакет можно подготовить и проверить повторно. Состояния с неизвестным итогом запуска продолжают учитываться защитой от повторов.

## Диагностика

| Код | Причина |
| --- | --- |
| `PACKAGE_STORAGE_INSUFFICIENT` | Для копии требуется больше места, чем доступно. Отчёт показывает оба значения в байтах. |
| `PACKAGE_SCHEMA_INVALID` | Поле расходится с правилами схемы, например счётчик вложений. |
| `UNSUPPORTED_PACKAGE_VERSION` | Версия манифеста, схемы имён или привязки неизвестна. |
| `ATTACHMENT_BINDING_INVALID` | Маркер, имя файла или идентификатор привязки расходятся с манифестом. |
| `MEDIA_ATTRIBUTES_INVALID` | MIME, атрибут или представление не соответствует типу вложения. |
| `MEDIA_HASH_MISMATCH` | Размер или контрольная сумма файла изменились. |
| `FILE_NOT_FOUND` | Отсутствует манифест, история или вложение. |
| `MANIFEST_MISMATCH` | Проверяемая копия, открытый проект или текст расходятся с сохранённым манифестом. |
| `PACKAGE_IO_ERROR` | Чтение или запись локального файла завершились системной ошибкой. |

Технический отчёт показывает этап, поле, файл, исходный ID при наличии, ожидаемое и фактическое значения и дальнейшее действие. Кнопка сохранения доступна и при сбое до создания операции. В классическом интерфейсе можно выбрать обезличенный вариант для передачи. Исходные сообщения и сессии не включаются в диагностический JSON.

## Проверки

- Повторная проверка исходного пакета с 312 сообщениями и 218 вложениями прошла при том же лимите. Она дошла до ожидания подтверждения в локальной имитации. История обеих прежних неудачных попыток сохранилась и не блокировала проверку.
- Синтетический пакет того же размера по числу записей прошёл проверку с одной копией. Отдельно проверены стикер без эмодзи, блокировка при недостатке места, повторная подготовка, точные ошибки повреждённых пакетов и экспорт отчёта без ID операции.
- На Windows прошли 24 теста GGE и 7 тестов C++-оболочки, включая проверку связи оболочки с Python-службой.
- Исходный пакет, рабочий реестр и авторизация оставались на локальном компьютере. Проверки API выполнялись на локальной подстановке.

## Установка

Распакуйте ZIP Fix 2 в отдельную папку и запустите `gTR.exe`. Этот запуск использует прежнее локальное хранилище проектов, настроек, авторизации и журналов. Установщик предыдущего Fix распознаёт имена выпусков только до первого номера исправления, поэтому для этого перехода нужна распаковка в отдельную папку.
