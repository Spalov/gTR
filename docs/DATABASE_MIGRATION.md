# Совместимость данных при обновлении

## Beta 5 и Beta 5 (Fix) → Beta 6

Данные живут в %LOCALAPPDATA%\gAssets\gTR. Установка Beta 6 не переносит их в каталог программы и не меняет схему проекта SQLite. Новая оболочка читает проекты и журнал через Python в режиме только для чтения. Прежний интерфейс использует действующий реестр операций, профили и Windows DPAPI. Для нативной оболочки добавлены собственные ключи настроек native/.

Свежий пакет схемы 3 содержит версию привязки, независимое имя передачи и идентификатор вложения. Пакеты старого формата читаются с их историческими именами. Точное повторное открытие сохранённого пакета предпочтительнее пересборки. Если пересборка даст другой SHA-256, прежняя операция остаётся закрыта для автоматического повтора. Для использования Beta 5 (Fix) сохраните её папку и подготавливайте пакеты средствами Beta 5 (Fix).

Оригиналы, сессии, результат сверки и журнал остаются на месте. Версия кеша учитывает профиль кодирования, поэтому возможна новая копия при сохранённой старой. Кеш очищается только по подтверждению. Резервная копия проекта доступна в прежнем интерфейсе.

## Более ранние версии

Проекты сохраняют каталог SQLite версии 1. На новые каталоги добавляются индексы сообщений и диагностики. Beta 5 открывает прежние каталоги только для чтения и извлекает доступные сведения о пересылках из старых полей. Для нового анализа видео можно подготовить новый пакет из прежнего проекта. Для сопоставления JSON и HTML нужно заново открыть исходный экспорт как отдельный проект с обоими форматами.

Схемы пакетов 1, 2 и 3 остаются читаемыми с действовавшими для них ограничениями. Beta 5 пишет схему 3 с дополнительным свидетельством о медиа и структуре, сохраняя исходную временную шкалу. Старый пакет с упорядоченными датами сохраняет то время, с которым был подготовлен. Для новой подготовки используется историческое время.

Локальные проекты, ключи DPAPI, сессии, настройки, профили, импортный журнал и результаты сверок живут отдельно от каталога приложения. Обновление версии не запускает изменение их форматов или перестройку существующей базы. Резервная копия проекта создаётся в «Архиве». Специальный тестовый реестр применяется только к разрешённой паре собственных тестовых аккаунтов, когда с обеих сторон подтверждена пустая история.

Разбор и подготовка выполняются во временных папках, каталог фиксируется транзакцией SQLite. Опубликованным считается результат атомарного переименования папки. После внезапной остановки может остаться временная папка, которую можно проверить и удалить локально. Операция Telegram, дошедшая до отправки запроса запуска, блокирует пересекающиеся записи до сверки по независимым снимкам. [Восстановление операций](SAFE_IMPORT.md)
