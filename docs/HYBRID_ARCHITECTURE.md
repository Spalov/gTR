# Архитектура gTR Beta 6

Оболочка Windows написана на C++20 и Qt 6 Widgets. Она владеет представлениями и состоянием мастера. При запуске она поднимает дочернюю службу на Python. Служба открывает проекты SQLite, импортирует локальные экспорты, анализирует медиа, готовит пакеты и сравнивает снимки. Протокол описан отдельно. [IPC](IPC_PROTOCOL.md)

Существующие адаптер Telegram/Telethon, защита от повторной отправки, работа с профилями, учётные данные DPAPI, журнал и ручная серверная сверка используются через окно прежнего интерфейса. Кнопка из шага «Результат» передаёт путь к проверенному пакету и связанному проекту. Она не отправляет пакет. Авторизацию и отправку пользователь запускает в открывшемся окне. Общий журнал остаётся владельцем состояний операции. [Сценарий импорта](OWNER.md)

Анализ и подготовка запускаются в фоне с ограниченными событиями прогресса. Служба допускает одну изменяющую задачу за раз. Для просмотров и поиска она возвращает порции строк. Анализ исходника и пакета публикует только завершённую папку, а чтение проекта идёт через SQLite в режиме только для чтения. Разрыв канала отменяет незавершённую локальную работу. После перезапуска пользователь может открыть сохранившийся проект и повторить локальную команду. Для неопределённого результата Telegram по-прежнему требуется отдельная сверка.

GGE-адаптер добавляет ограниченное чтение, разбор заголовков ZIP, просмотр метаданных и отдельный медиапроцесс. Отдельный кодек на C и зависимость от .NET не потребовались. Преобразование использует установленные FFmpeg и FFprobe. Нативный плеер использует Windows Media Foundation через Qt Multimedia. [Медиа](MEDIA_ENGINE.md)
